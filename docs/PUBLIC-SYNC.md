# 公开仓库同步规则

本仓库是 OpenClaw Execution Gate 的**脱敏公开发行版**，不是生产服务器 Git 仓库的直接镜像。两者可能使用独立的 Git 历史。不要把生产目录直接设置为本仓库的上游并整仓推送，也不要用 `--force` 覆盖公开发行历史。

## 发布边界

- 仅同步可复用、与个人业务无关的源码、测试、示例和文档。
- 保留公开发行版已有的安装器、脱敏校验、示例配置和恢复说明。
- 生产专用的账号、身份、Cron Job ID、服务器路径、地址、MCP 凭据、业务脚本、账单和运行状态不得进入公开提交。
- 不提交 `.env`、生产 `openclaw.json`、密钥、Token、数据库、日志、缓存、会话、个人工作区或备份。
- 所有公开配置使用占位符或环境变量引用；生产环境中的绝对模块路径须改为可移植的导入方式。
- 未提交、未验收的生产工作区改动不得当作稳定版本发布。

## 同步和验收方式

1. 在独立的临时发布工作区，以 GitHub 现有 `main` 为基线，逐项筛选通用改动；不要修改生产工作区。
2. 检查差异和新增路径，并进行秘密扫描与私人数据扫描，检查新提交和可恢复的 Git 历史。
3. 运行 `npm test`、`npm run build`、`npm run verify`。安全或审批逻辑有变动时，还需要在隔离环境验证审批冻结、单次消费和拒绝路径。
4. 检查安装、升级和回滚行为后，才更新正式发行版本、变更日志及 GitHub `main`。
5. 保留原有公开历史，使用正常提交或拉取请求；禁止以强制推送解决独立历史分叉。
